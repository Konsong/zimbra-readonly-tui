Since the last survey

Its §1 — the gate's own codes re-decided per module — has landed: lib/settle.sh exists, zro_exec_own_code owns the predicate, ZRO_ERROR_KEEP_BYTES replaced the 500-byte literal at all twelve sites, and ADR-0010/0011 record what deliberately did not move. This review does not re-propose it. It reports what the migration left, and what four fresh walks found around it.

Problem

The settler's name check asks whether a name is shaped like a failure reader and whether a function answers to it, but not whether that function can be called with the one argument the settler passes — and two of the five readers in this tree cannot.

Solution

Add the third question to the same predicate, so a wrong name is refused for the reason that actually breaks the settler rather than only for the reason that is easy to check.

Evidence — verified

Under set -u with no errexit, the assignment fails, zro_settle prints nothing, and the caller's [ "$rc" -eq 0 ] errors on an empty string — the operator gets a code this program does not define, and neither refusal is logged, because neither fires.

ADR note — not a conflict

ADR-0010 states the check is “a defence against an edit”. This does not reopen that decision; it reports that the stated property is not achieved, and that the two names an edit is most likely to reach for are exactly the two that slip through.

Wins
  • locality: one predicate, one edit
  • the refusal fires where it was meant to
  • defect reaches the log, not the screen
  • interface unchanged; implementation absorbs it
Deletion test The check cannot be deleted — it is the module's only test. It is one question short, not surplus.
