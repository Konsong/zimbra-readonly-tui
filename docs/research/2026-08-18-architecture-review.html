This codebase is unusually well-reasoned: lib/table.sh and the exec gate's allowlist are the two deepest modules in the tree, and tests/lib/cost.sh is the best-shaped assertion in the suite. Everything below is friction that has already produced drift — in one case, a live defect on screen.

2 · The declared cost is checked but never spoken

Strong in-process
zimbra-ro-tui.sh:2906:2959:3003:424:630 :1412:1466:1641:1832:2272:2711
Before — declaration and disclosure never meet
After — the declaration is load-bearing
Problem

Every operation declares a cost class and every class declares a unit — and zro_menu_cost has zero callers in the program. What an operator reads before spending is hand-written five ways, and the two case lists disagree about failure: zro_mailbox_cost_note's default logs a defect (:672), zro_account_cost_note's silently prints a generic sentence (:438). Add a mailbox-* operation without a note and the build shouts; add an account-* one and nothing does.

Solution

A cost-note module keyed on the operation id that reads class and unit from the one list. Absence is a refusal, in the shape lib/table.sh already established.

Wins
  • the declaration stops being decorative
  • locality: one place the class and the sentence must agree
  • a sixth mechanism cannot be invented
  • test surface joins assert_cost, which already reads the unit

3 · A partial answer is a value, not a code plus a habit

Strong in-process

After — one thick band

Problem

Three modules produce ZRO_E_PARTIAL and each builds its own banner; then three screens each hand-write a title. Two hard-code a title instead of reading the one from ZRO_MENU_OPS, and they use two different suffix words. The shared reporter's arm shows a message box and is never handed $out — so the fourth screen to return 30 discards both the answer and the banner the module worked to write.

Solution

Partiality travels as an answer rather than a status. One module carries body, banner and title together; the exit code stays for callers that must branch.

Wins
  • the disclosure cannot be dropped by forgetting
  • locality: one definition of “how much was selected”
  • four renderings of one code collapse to one
  • leverage: a fifth partial producer costs nothing
Not an ADR conflict. CONTEXT.md §Reduced service requires both halves — “both are disclosed and both report the partial code.” This candidate makes that requirement structural instead of remembered.

5 · An operation is declared once and re-matched five times

Worth exploring in-process
zimbra-ro-tui.sh:2959:3047:3104:3300 :424:630preamble at :451 :540 :700 :972 :1184
Before — one id, five case lists
After — the declaration answers all five
Problem

ZRO_MENU_OPS declares four fields; four more per-id decisions live in scattered case lists, each with its own defect branch. The account-scoped preamble is copied five times, differing by one word. And zro_menu_entry is dead: its comment claims “every lookup below goes through this”, and its three siblings call lib/table.sh directly instead.

Solution

Widen the declaration; one dispatcher reads it. The refused-flag rule this project already trusts — absence is a refusal — turns four runtime defect branches into build failures.

Wins
  • adding an operation is one row
  • locality: the tenth screen inherits the preamble
  • 44 zro_report_defect sites shrink
  • subsumes candidate 2's cost note
Sequencing. Largest blast radius of the seven. Worth doing after 2 and 4, which each remove one of its five sites.

6 · One record reader instead of eight

Worth exploring in-process
lib/account.sh:49,58,111,173lib/mailset.sh:252,311 lib/identity.sh:61lib/directory.sh:191,235
Before — interface as tall as the implementation

Problem

key: value is one output shape with eight readers. Two of them reimplement zro_attr_get's rule — once in awk, once in parameter expansion with the attribute names hard-coded — because what they actually need is a record boundary, and the record reader does not exist. The continuation rule has three implementations whose comments each name the other two.

Solution

A record reader: split records, then read fields. The continuation rule gets one home; lib/identity.sh's synthetic records already prove the shape travels.

Wins
  • locality: the truncated-rule-set failure gets one guard
  • the # header is parsed once, not twice
  • leverage: a fourth child-entry read is free
Keep out: ZRO_SEARCH_PROMPTS. ADR-0009 explains why that shape stays separate — folding it in buys a parameter meaning which of two readers am I.

7 · The suite's preamble is an interface nobody wrote down

Worth exploring mock
tests/lib/ (153 lines)51 test files16 mockstests/mocks/mock_common.sh
Before — preamble mass vs assertion mass
After — the seam is the setup
Problem

Twenty facts are needed to stand a module up — four root variables that must differ, three full-path variables, two priority wrappers needed only for some modules, a mock log whose absence makes assertions pass vacuously, five session resets in five modules that nothing composes. None is enumerated anywhere. The 69-line median preamble is that enumeration, re-derived 51 times.

The suite also asserts 371 times against a transcript string and 59 against a return value — and eight of test_store_screen.sh's card assertions are verbatim duplicates of test_store.sh's, one indirection later.

Solution

Grow tests/lib/ to carry the seams: one env setup, one UI driver, one gate stager, one composed reset. Model it on tests/lib/cost.sh, which already reads the declaration rather than restating it.

Wins
  • leverage: 51 files, one setup
  • the stub's line format stops having 8 consumers
  • the existence gate gets one dialect, not two
  • a screen test can spend its lines on ordering and cost
Coverage gradient, for context. 188 of 461 functions are never named in a test. The four modules at 0% untested — selection, table, validate, window — are exactly the four that take values and return values. zimbra-ro-tui.sh sits at 76% untested. The gradient tracks depth precisely, which is the argument for candidates 1–5 restated as a measurement.

Top recommendation

1 · One settler at the exec seam

It is the only candidate whose friction has already reached the operator: an allowlist denial on zmmetadump — the exit code this project defines as a defect in itself — is currently rendered as “mailboxd is stopped.” The rule that would prevent it is written six times in three versions, and the module that gets it wrong gets it right thirty lines further down.

It is also the cheapest deep module in the list. The three settlers are already byte-identical; what is missing is a name for them. The mapper travels as a name, which is the convention ADR-0009 settled — so the seam is one this codebase has already argued for and can reuse rather than relitigate.

Then 4 (hours, pure move), 2 and 3 (each removes a site from 5), and 5 last, when its blast radius is smallest.
